## 1. Технический SEO

### Критично (блокирует индексацию и репутацию ссылки)

| Что | Факт | Последствие |
|---|---|---|
| `robots.txt` | **отсутствует** | Нет правил обхода, нет указания на sitemap |
| `sitemap.xml` | **отсутствует** | Робот обходит только по ссылкам, новые страницы находит медленно |
| `rel="canonical"` | **0 из 11 страниц** | `/`, `/index.html`, `/?utm_source=...` — три дубля одной страницы |
| Open Graph / Twitter Card | **0 из 11 страниц** | Ссылка в Telegram, WhatsApp, Slack выглядит голой строкой без картинки и описания. Для B2B-переписки это прямая потеря доверия |
| JSON-LD микроразметка | **0 из 11** | Нет Organization, LocalBusiness (Пермь!), Service, FAQPage, BreadcrumbList → нет расширенных сниппетов и карточки организации |
| `apple-touch-icon`, `manifest` | нет | На iOS иконка «на экран» будет мыльной |

### Что сделано хорошо

- Чистые URL без `.html` + 301-редиректы со старых адресов (`.htaccess`).
- `lang="ru"`, `charset`, `viewport`, favicon — на всех страницах.
- Ровно один `<h1>` на каждой странице, иерархия h1 → h2 → h3 не нарушена.
- Уникальные `title` (48–58 символов) и `description` (70–130 символов) на всех 11 страницах — длины в норме.
- 404 отдаёт правильный код и не индексируется, `cabinet` закрыт `noindex`.
- Внешние ссылки все с `rel="noopener"`.

### Производительность (влияет на ранжирование)

| Метрика | Факт | Норма |
|---|---|---|
| Вес первого экрана | **≈ 610 КБ** (hero 408 КБ + CSS 33 + HTML 19 + логотип 146) | до 300 КБ |
| Все изображения | **4,4 МБ**, 19 файлов JPEG/PNG | — |
| Формат | **0 файлов WebP/AVIF** | WebP экономит 30–50 % |
| `preload` для hero | **нет** | LCP-картинка грузится с задержкой |
| Логотип | PNG 146 КБ, показывается 26×26 px | должен быть SVG или 8 КБ |
| Шрифты | 2 семейства с Google Fonts, без `preconnect`-фолбэка на локальные | — |

Ожидаемый LCP на 4G: **3–4 с** вместо целевых 2,5 с. Это уже фактор ранжирования.

|---|---|

| заказать сайт | **0** |
| разработка сайтов в Перми | **0** |
| заказать телеграм-бота | **0** |
| стоимость | 2 |
| Пермь | 13 |

Тексты написаны живым человеческим языком (это плюс для конверсии), но **не содержат ни одной фразы, по которой вас реально ищут**. Поиск не понимает, что вы продаёте.

Объём текста: 133–424 слова на страницу. Для конкурентных коммерческих запросов в топе обычно 800–1500 слов на посадочной.

Чего не хватает структурно:
- Нет посадочных под отдельные запросы: `/services/sites`, `/services/telegram-bots`, `/services/games` — сейчас всё на одной странице услуг, конкурировать нечем.
- Нет гео-страницы «Разработка сайтов в Перми» — при том, что вы локальный игрок и это самый дешёвый трафик.
- Нет блога / базы знаний. В B2B органика растёт именно через статьи («сколько стоит интернет-магазин», «чем бот отличается от приложения»).
- Нет хлебных крошек (и разметки BreadcrumbList).

## 3. Маркетинг и конверсия

### Что работает

- Цены названы прямо, четыре тарифа, разбор факторов цены — это редкость на рынке и сильно повышает доверие.
- Хорошие снятия возражений: «прототип до кода», «правки бесплатны», «исходники ваши», «месяц гарантии».
- Один CTA-цвет (янтарь) и он не размазан по странице — внимание идёт куда надо.
- FAQ закрывает реальные вопросы, а не выдуманные.

### Что теряет заявки

| Проблема | Почему больно |
|---|---|
| **Нет телефона** | В РФ 30–50 % обращений в малом бизнесе идут звонком. Сейчас нет ни номера, ни кнопки звонка |
| **Нет виджета быстрой связи** | Telegram-ссылка есть текстом, но нет плавающей кнопки — путь до диалога длиннее, чем у конкурентов |
| **Нет ни одного отзыва** | Ноль социального доказательства: ни отзывов, ни логотипов клиентов, ни ссылок на профили |
| **Нет команды** | Ни имён, ни лиц, ни опыта. При этом главный аргумент сайта — «с вами говорят те же люди, что пишут код». Утверждение ничем не подкреплено |
| **Один кейс** | Dope Music — единственная работа, и та без результата: нет «стало X заявок», «сократили Y времени» |
| **Форма только длинная** | 4 поля — нормально, но нет быстрого варианта «оставьте телефон, перезвоним за 15 минут» |
| **Нет лид-магнита** | Нечего скачать/получить тем, кто ещё не готов писать: ни чек-листа, ни примерной сметы |
| **Нет счётчиков** | Яндекс.Метрика и GA отсутствуют. Вы не узнаете ни источник заявки, ни конверсию, ни где люди уходят |

### Техническая дыра в приёме заявок

Форма отправляет на `../marketing-site/send.php`, то есть в папку **старой версии сайта**. Если v2 выложить в корень домена (как и планируется), путь развалится и заявки будут уходить только через `mailto`-фолбэк — то есть фактически теряться. Это надо чинить до публикации.

## 4. B2B-готовность

Что решает корпоративный клиент, глядя на сайт: «можно ли с ними заключить договор и не подставиться».

| Требование B2B | Есть? |
|---|---|
| Реквизиты (ИП/ООО, ИНН, ОГРН) | **нет — заглушки `[наименование ИП или ООО]`** в `privacy` и `terms` |
| Договор, закрывающие документы | упомянуто в тексте — хорошо |
| Условия работы, этапы, приёмка | **есть, сильная страница** |
| SLA (время реакции) | частично: «ответ на сбой в течение двух часов» в тарифе поддержки |
| NDA / конфиденциальность | пункт в условиях есть, отдельного упоминания NDA нет |
| Команда с именами и ролями | **нет** |
| Кейсы с измеримым результатом | **нет** |
| Отраслевая экспертиза | не заявлена |
| Работа по 44-ФЗ/223-ФЗ, счёт, отсрочка | не упомянуто |
| Безопасность данных, где хостится | не упомянуто |

Вывод: **юрлицо не сможет вас проверить и завести в закупку.** Пока сайт работает только на входящих по рекомендации.

## 5. B2C и малый бизнес

Что решает владелец кафе, барбершопа, частный мастер: «сколько, как быстро, не обманут ли».

Сильно: цены прямо на сайте, простой язык без жаргона, сроки по каждому направлению, «правки бесплатны».

Слабо:
- Нет телефона и мессенджер-кнопки — этой аудитории писать почту непривычно.
- Нет рассрочки/этапной оплаты как оффера (в условиях есть аванс по этапам, но это не подано как выгода).
- Нет примеров «как у меня»: сайт для кафе, бот для записи в салон. Есть только студия звукозаписи.
- Нет ответа на страх «а что если я не разбираюсь» — хотя FAQ про ТЗ это частично закрывает.

## 6. Юридическое (важно для обеих аудиторий)

- В `privacy` и `terms` **реквизиты оператора — заглушки**. Документы в таком виде юридически пустые.
- **Нет чекбокса согласия** на обработку персональных данных. Сейчас только текст «нажимая, вы соглашаетесь». Роскомнадзор трактует это как слабую форму получения согласия; для B2B-проверок нужен явный чекбокс с ссылкой на политику.
- Нет уведомления о cookie. Формально вы ставите только техническую cookie темы, но уведомление всё равно принято показывать.
- Нет ИНН/ОГРН в подвале — обычная практика доверия в РФ.

## План работ по приоритетам

### P0 — до публикации (примерно один заход)

1. Починить путь формы заявки (иначе заявки теряются).
2. `robots.txt` + `sitemap.xml` + `canonical` на всех страницах.
3. Open Graph и Twitter Card + og-картинка 1200×630 (Вант на рассвете).
4. JSON-LD: Organization + LocalBusiness (Пермь) + Service ×4 + FAQPage.
5. Яндекс.Метрика с целями (отправка формы, клик по почте, клик по Telegram).
6. Телефон + кнопка звонка в шапке и подвале.
7. Чекбокс согласия на обработку ПД в форме.
8. Реквизиты вместо заглушек в `privacy`, `terms` и подвале.

### P1 — первые две недели

9. Сжать картинки в WebP + `preload` hero + логотип в SVG (вес первого экрана с 610 до ~200 КБ).
10. Отдельные посадочные под запросы: сайты / боты / приложения / игры, плюс «Разработка сайтов в Перми».
11. Переписать тексты с вхождением коммерческих запросов, объём до 800+ слов на посадочную.
12. Блок «Команда»: имена, роли, опыт.
13. Кейс Dope Music дополнить результатом в цифрах, добавить 2–3 кейса (можно анонимные: «сеть кофеен», «сервисный центр»).
14. Плавающая кнопка Telegram/WhatsApp.

### P2 — дальше

15. Отзывы клиентов (текст + ссылка на профиль или скан благодарности).
16. Блог: 5–7 статей под информационные запросы.
17. Хлебные крошки + BreadcrumbList.
18. Лид-магнит: «Чек-лист: что уточнить у подрядчика до старта» в обмен на контакт.
19. Блок для B2B: работа по счёту, отсрочка, NDA, безопасность данных.
